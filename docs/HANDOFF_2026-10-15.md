## Where things stand

- Pipeline (`ml/`) is complete and committed: clean splits, Modal TRL training, bf16 eval,
  GGUF conversion + 11 quants + llama.cpp eval, report.
- 8 runs trained (4 models x json/two_phase, LoRA r=16, 5 epochs). All merged models, GGUFs
  and eval JSONs are in the Modal volume `hishab-runs` under `/runs/<model>__<fmt>__lora/`.
- Published: dataset `ryuma007/hishab-synthetic-v3`; GGUF repos
  `ryuma007/hishab-qwen3.5-0.8b-json-lora-GGUF`, `...-lfm2.5-350m-two-phase-lora-GGUF`,
  `...-lfm2.5-1.2b-two-phase-lora-GGUF`, each with a model card and `eval/`.
- Ship candidate: Qwen3.5-0.8B json Q4_K_M-imat (529 MB, 85.5% exact on the held-out test).
  Verified in kiln on the Linux desktop with `kiln-cli --raw` (about 43 tok/s on 8 threads);
  all five probe messages correct except "basha vara" labelled `other` instead of `rent`.
- Data round two (same day): 5000 programmatic rows from `ml/data/generate_banglish.py` plus
  155 hand-written rows, train split only. Retrains tagged `v4` and `v5` (v5 adds spelled-out
  number words and 42 targeted rows). Qwen json: 87.6 (v3) -> 87.8 (v4) -> **88.2 (v5)** bf16,
  Banglish 81.7 -> 84.0. LFM2.5-350M two_phase: 83.0 -> 84.2 (v4). GGUFs published as
  `ryuma007/hishab-qwen3.5-0.8b-json-lora-v5-GGUF` (Q4_K_M-imat 84.6, Q6_K 86.5, Q8_0 86.1)
  and `ryuma007/hishab-lfm2.5-350m-two-phase-lora-v4-GGUF` (Q4_K_M 82.8, Q5_K_M 84.7, Q8_0 84.6).
  At Q4_K_M-imat the v3/v4/v5 Qwen scores (85.5 / 85.1 / 84.6) are within noise of each other
  (one test row is 0.19 points); v5 is preferred because it fixes concrete behaviours
  (number words, medicine, loan direction, data packs) that matter for real users.
- `ml/results/ERROR_ANALYSIS.md`: of the ~60 remaining Qwen errors, most are label-convention
  disagreements in the Gemini gold. Next real gain needs a relabelled test set with a written
  guideline and real user messages, not more training data.

## Per-machine setup on a new computer

- `conda` env `ML` with `pip install modal`; `modal token new` (workspace cortex-technologies).
- Modal secret `huggingface-secret` already holds a valid `HF_TOKEN` (fine-grained, write).
- `.env` is not in git: copy it by hand (or recreate from `.env.example`).
- Claude Code memory lives in `~/.claude/projects/-<path-to-repo>/memory/`; copy that folder
  if you want the agent to remember the pitfalls listed in `hishab-v3-results.md`.
- For kiln on the Mac: `cmake --preset host && cmake --build --preset host -j`, then download the
  GGUF from the HF repo above into `kiln/models/`.
